Downpour — Browser integration

Pairing token

Open Downpour → Settings → Browser integration, copy the 64-character token and paste it here. Every request except the health check is rejected without it, which is what stops ordinary web pages from queuing downloads into your app.

Download capture

Capture downloads

When on, a matching download is cancelled in the browser and handed to Downpour with its cookies, referer and user-agent. If the app is not running the browser keeps the download — nothing is ever lost.

Use the rules from the Downpour app

Follow the size floor and extension lists configured in the desktop app (/api/v1/capture, re-read every 30 seconds). Turn this off to use the browser-side rules below instead. The app's list of excluded hosts is honoured either way — a host the app refuses to handle is not worth sending it.

Video button

Show a download button over videos

A small pill fades in at the top-right of a video when you hover it, or after it has been playing for about two seconds. It never appears on page load, never over a page without a real video, and never in fullscreen. Clicking it lists what can be downloaded; everything else on the page is left alone.

One host per line (or comma separated); subdomains are included. The button's own “Don’t show this on …” entry adds to this list, and takes effect in every open tab straight away.

A video file the page links to directly is offered straight away — no desktop app needed. For a player that streams in pieces (YouTube and most large sites) the button asks Downpour for the real quality list, which needs yt-dlp installed in the app under Settings → Video pages. Formats with video and sound are listed first; anything that would arrive without audio is put behind a “show more” link and labelled, because Downpour bundles no ffmpeg to join the two back together.

Bypass key

Hold this key while starting a download to let that one download go to the browser instead of Downpour — no need to turn capture off and back on. The key counts if it was held within about two seconds of the download starting.

Note that Chrome already treats Alt+click on a link as “download this”, which is why Alt is the default: Alt+click means “download it here, in the browser”. Ctrl and Shift change what a click does in Chrome (new tab, new window), so they are better held while starting a download some other way. On macOS, Cmd counts as Ctrl.

Per-site rules

These always apply, whether the rules above come from the app or from the browser. One host per line (or comma separated). Subdomains are included: example.com also covers files.example.com. Both the download's own host and the page that started it are checked, so a site that serves its files from a separate CDN is still covered.

The popup's “Never capture from this site” switch adds and removes entries here.

Leave this empty unless you want capture off by default. When it has any entry, every other site is skipped.

Browser-side rules

Used only when “Use the rules from the Downpour app” is off.

0 means no size floor. Downloads whose size the browser does not yet know are always considered — the size is often unknown at capture time.

Subdomains are matched too: example.com also excludes files.example.com.

Downpour speaks protocol version 1 on 127.0.0.1 ports 47113–47123. Nothing is sent anywhere else.
